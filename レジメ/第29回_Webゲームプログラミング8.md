### 2. うまく動かないときの調べ方

#### (1) コンソールのエラーを読む

`F12` の開発者ツールのコンソールに、赤字でエラーが表示される。エラーの右側には、エラーが起きたファイル名と行番号（例：`main.js:85`）が表示される。まず、その行を見る。

よく出るエラーと、主な原因：

| エラーの表示（一部） | 主な原因 |
|---|---|
| `ReferenceError: ○○ is not defined` | 変数名・関数名の綴りの間違い。作っていない変数や関数を使っている |
| `TypeError: Cannot read properties of undefined (reading 'y')` | 配列のない番号（`bullets[5]` など）の `.y` を使おうとした。`for` の条件が `<=` になっている、`break` を忘れた、など |
| `SyntaxError: Unexpected token '}'` | `{ }` や `( )` の数が合っていない。`,` や `;` の書き忘れ・書きすぎ |
| `TypeError: Cannot read properties of null (reading 'getContext')` | `getElementById("game")` の名前と、`<canvas>` の `id` が違う |

- エラーが 1 つ出ると、そこから先の処理が実行されないことがある。上に表示されたエラーから順に直す。

#### (2) エラーが出ないのに、思いどおりに動かないとき

エラーが出なくても、条件の書き間違いなどで、思いどおりに動かないことがある。

- **コンソールに変数名を入力する**（第 26 回）：コンソールに `score` や `lives`、`enemies.length` などを入力して `Enter` キーを押すと、その時点の値が分かる。
- **`console.log` を一時的に書く**：たとえば、弾が当たったときに得点が増えているかを調べたいときは、`checkBulletHits` の `score += 100;` の下に `console.log(score);` を一時的に書く。当たるたびに、コンソールに得点が表示される。確認したら、その行は消す。
  - `update` の最初などに書くと、1 秒に 60 回表示されて読めなくなる。`if` の中など、たまにしか実行されない場所に書く。
- **1 行ずつ `//` で止めてみる**：あやしい行の先頭に `//` を付けて、動きがどう変わるかを見る（第 22 回・第 24 回・第 28 回の演習で行った方法）。
- **キーを離しても自機が止まらないとき**：キーを押したまま、ブラウザの外（別のウィンドウなど）をクリックすると、キーを離したこと（`keyup`）がブラウザに伝わらず、`isLeftPressed` などが `true` のまま残って、自機が動き続けることがある。ゲームの画面をクリックしてから、同じキーをもう一度押して離すと止まる。

### 3. 見た目の調整

#### (1) 色の指定

`ctx.fillStyle` には、CSS と同じ書き方で色を指定する。

| 書き方 | 例 | 意味 |
|---|---|---|
| `#rrggbb` | `"#ff4444"` | 赤・緑・青の強さを、それぞれ 2 けた（`00`〜`ff`）で書く |
| 色の名前 | `"white"`、`"orange"` | 決まった名前の色 |
| `rgba(赤, 緑, 青, 透明度)` | `"rgba(0, 0, 0, 0.6)"` | 赤・緑・青は 0〜255、透明度は 0（透明）〜1（不透明） |

- 背景を暗い色にして、自機・弾・敵・文字を明るい色にすると、見やすい。
- 自機と敵は、はっきり違う色にする。

#### (2) 複数の四角形で形を作る

`drawPlayer` の中で、`fillRect` を何回か使うと、四角形を組み合わせて、翼のある機体などの形にできる。

- 位置は、`player.x + 12` や `player.y + 20` のように、**`player.x`・`player.y` をもとに計算する**。こうすると、自機が動いても、形がくずれずに一緒に動く（第 21 回の発展と同じ考え方）。
- 当たり判定（`isHit`）は、これまでどおり `player` の `x`・`y`・`w`・`h` の四角形で行われる。描く形は、この四角形からはみ出さないようにすると、見た目と当たり判定がずれない。
